# Zang P4 pinout: board v0.0.1

Source: `Zang v0.0.1 Schmeatics.pdf`. The findings, the strapping table, camera timing and display frame-rate maths
are in **[HARDWARE_REVIEW.md](HARDWARE_REVIEW.md)**. Read that first.

Every pin is a Kconfig option (`idf.py menuconfig` → **Zang board pins**). The defaults equal the schematic, and you can
override any of them. A driver whose required pins are `-1` is skipped at boot; that is not an error. At boot,
`board_init()` prints the table and rejects duplicate or out-of-range pins. The table below and the Kconfig entries are
generated from one list in `tools/gen_board_pins.py`. Edit that list, then run `python3 tools/gen_board_pins.py`.

## ⚠ v0.0.1 rework wires (the board won't move without the first one)

| # | Rework | Why |
|---|---|---|
| 1 | **`SS_P` → GPIO47, `SS_N` → GPIO48** | The servo bus nets reach no P4 pin (HARDWARE_REVIEW finding 1). Firmware drives GPIO47 as an open-drain UART TX and reads GPIO48 as RX. |
| 2 | Camera PWDN (connector pin 17) → GND | It floats; on an OV2640 a high PWDN powers the sensor down (finding 4). |
| 3 | TFT RESET (FPC pin 11) → 10 kΩ to 3V3 + 1 µF to GND, or a free GPIO | It seems unconnected (finding 6, VERIFY). Firmware sends SWRESET either way. |

## Co-processor link (ESP-Hosted over UART)

The ESP-Hosted component owns its pin options, so `sdkconfig.defaults` sets them to the same GPIOs as the
`C2_*` entries above, and `components/net` stops the build with `#error` if they ever differ.

| Signal | P4 | ESP-Hosted option | C2 (ESP8684) |
|---|---|---|---|
| P4 RX ← C2 TX | GPIO26 | `ESP_HOSTED_UART_PIN_RX` | U0TXD = GPIO20 |
| P4 TX → C2 RX | GPIO27 | `ESP_HOSTED_UART_PIN_TX` | U0RXD = GPIO19 |
| C2 reset | GPIO29 | `ESP_HOSTED_UART_GPIO_RESET_SLAVE` | CHIP_EN |
| C2 boot mode | GPIO28 | (firmware `net_c2_reset()`) | GPIO9 strap |

The C2 uses UART0, its ROM download UART, for ESP-Hosted. Because the P4 also controls the C2's EN and BOOT pins, it can
later flash the C2 over this same link with `esp-serial-flasher`.

## ESP32-P4 rules worth remembering on v0.0.2

| Pins | Rule |
|---|---|
| GPIO34–38 | Straps (GPIO35 boot, GPIO36 must read 1 for download, 37/38 UART0). Never drive them during reset. Firmware never uses them. |
| GPIO24/25 | USB-Serial-JTAG: flashing and console. Keep them. |
| GPIO39–44 | SDMMC slot-0 IOMUX pins: CLK 43, CMD 44, D0 39, D1 40, D2 41, D3 42. The board uses another order, so it runs on slot 1 through the GPIO matrix (≤ 40 MHz). Re-order them on v0.0.2 only if UHS-I is needed. |
| MIPI DSI/CSI, flash | Dedicated pins, not GPIOs. |
| GPIO0/1 | 32 kHz crystal pads. GPIO2–5 = pad JTAG. |
