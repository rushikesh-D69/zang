# Zang firmware

Two ESP-IDF projects for **Zang board v0.0.1** (`docs/Zang v0.0.1 Schmeatics.pdf`):

| Project | Chip | Role |
|---|---|---|
| `zang_p4/` | ESP32-P4 | Main controller: 15 DS serial servos, TFT face, DVP camera, speaker + 2 PDM mics, SD card, ZLink to the AI stack |
| `zang_c2_hosted/` | ESP32-C2 (ESP8684) | Wi-Fi co-processor: ESP-Hosted slave over UART. The P4 sees normal `esp_wifi` and lwIP sockets |

Read these first:
- [docs/HARDWARE_REVIEW.md](docs/HARDWARE_REVIEW.md): schematic findings. **The servo bus needs a rework wire on
  v0.0.1.**
- [docs/PINOUT.md](docs/PINOUT.md): net → GPIO table and free pins.
- [docs/ZLINK.md](docs/ZLINK.md): the host ↔ robot protocol (canonical).
- [docs/datasheets/INDEX.md](docs/datasheets/INDEX.md): datasheets.

## Build, flash, test

ESP-IDF **v5.5.6** (installed under `~/.espressif`). Run one build at a time with `-j2`; the laptop has 15 GB of RAM.
`firmware/Makefile` sources the IDF environment itself. Run `make help` for every target.

```bash
cd firmware
make build               # P4 app + C2 co-processor (JOBS=2)
make p4-flash-monitor    # flash + serial monitor over USB-Serial-JTAG (PORT=/dev/ttyACM0)
make c2-flash            # see zang_c2_hosted/README.md
make test                # gen-check, then every host test (ZLink vectors, servo, limiter, faces, engine, media)
make gen                 # regenerate robot_joints / board pins / faces_lib from ai_stack/config
make stop                # free the serial ports (kills monitor / esptool / openocd)
```

Manual equivalent:

```bash
source ~/.espressif/tools/activate_idf_v5.5.6.sh

# P4 main firmware
cd firmware/zang_p4
idf.py set-target esp32p4          # first time only
idf.py build -- -j2
idf.py -p /dev/ttyACM0 flash monitor   # USB-Serial-JTAG on GPIO24/25

# C2 co-processor (see zang_c2_hosted/README.md for flashing)
cd ../zang_c2_hosted
idf.py set-target esp32c2
idf.py build -- -j2

# Host unit tests (plain gcc + ASan/UBSan, no IDF)
cd ../zang_p4/test_host
cmake -S . -B build && cmake --build build -j2 && ctest --test-dir build --output-on-failure
```

Wi-Fi credentials: `idf.py menuconfig` → *Zang network*. They can also be set at runtime in NVS (`net_set_credentials`).
The robot advertises itself as `zang.local` with `_zlink._udp` on port 4210 and `_zlink._tcp` on port 4211.

## Layout (`zang_p4/components/`)

Each component has a small public header and returns `esp_err_t`; handles are opaque. Modules marked **pure** have no
IDF dependency and are compiled by `test_host/`.

| Component | What it does |
|---|---|
| `zang_common` | `zang_tasks.h`: the **one** table of task names, stacks, priorities and cores. Unit helpers and shared warning flags. |
| `board` | Pin table (Kconfig, defaults from the schematic, generated by `tools/gen_board_pins.py`), boot-time pin report and validation, shared I2C bus, battery ADC. |
| `robot_def` | **Generated** joint table from `ai_stack/config/robot.json` (`tools/gen_robot_joints.py`). |
| `servo_bus` | DS servo protocol: `ds_proto.c` (**pure** packet codec), `servo_bus.c` (half-duplex UART, open-drain TX, echo skipping, optional SYNC WRITE). |
| `zlink` | `zlink.c` (**pure** ZLink v1.1 codec: frames, CRC, stream resync, every message incl. STATE 88/96 B and the optional `ticks_per_rev`), `zlink_server.c` (UDP 4210 / TCP 4211). |
| `motion` | `motion_math.c` (**pure**: calibration, last-line limiter, trajectory interpolation, `.zact`), `motion.c` (core-1 task: modes, watchdog, file player), `motion_calib_nvs.c`. |
| `display` | SPI TFT (ST7789 / GC9A01 / ILI9341): PSRAM framebuffer, dirty-rect flush through 2 DMA line buffers, modes face / image / text / camera preview / status. **Pure:** `face_sdf.c` (SDF face renderer, a port of `ai_stack/zang_ai/face/render.py`), `face_engine.c` (blend, idle blink/gaze, talking, FACE_PARAMS, FACE_TRACK), `faces_lib.c` (**generated** from `faces.json` by `tools/gen_faces.py`), `canvas.c` (text, scaling), `img_asm.c` (DISPLAY_IMAGE reassembly). IDF: `display.c`, `zjpeg.c` (P4 hardware JPEG decoder). |
| `camera` | OV2640 on the P4 DVP controller (XCLK 20 MHz from GPIO13, SCCB soft reset). The sensor produces JPEG; QVGA 320x240 or VGA 640x480 and the quality are switched at run time (`camera_configure`). |
| `audio` | NS4168 on I2S (16-bit, rate follows the content) + 2 PDM mics via PDM2PCM; WAV playback, host PCM streams, playback clock. |
| `storage` | SD card on SDMMC slot 1 through the GPIO matrix (the board isn't on the slot-0 IOMUX pins), FAT at `/sdcard`. |
| `imu` | Optional QMI8658 + complementary filter. **Off**: no IMU on v0.0.1. |
| `net` | Wi-Fi STA through ESP-Hosted (UART, 3 Mbaud), mDNS, `net_c2_reset()` (EN_C2/BOOT_C2). Compile-time check that the Hosted pins match the board table. |
| `app` | `app_sm.c` (**pure** state machine), `app.c` (ZLink dispatcher, STATE publisher, events), `app_media.c` (face / display / image / camera / microphone messages). |

## Data path and message handling

```
PC / studio --Wi-Fi (UDP 4210 real-time, TCP 4211 bulk)--> ESP32-C2 --UART 3 Mbaud (ESP-Hosted)--> ESP32-P4 (lwIP)
                                                                                                        |
  servos  <-- UART half-duplex GPIO47/48 (DS protocol) <-- motion (limiter, 50 Hz) <-- JOINT_TARGETS / TRAJ_CHUNK
  TFT     <-- SPI GPIO19-23 <-- display (face_sdf renderer, framebuffer) <-- FACE_* / DISPLAY_*
  speaker <-- I2S GPIO30/31/33 (NS4168) <-- audio <-- AUDIO_CHUNK / PLAY_FILE
  mics    --> PDM2PCM GPIO45/46 --> audio --> MIC_CHUNK                      (CMD MIC_STREAM)
  camera  --> DVP GPIO5-16 --> camera (JPEG) --> CAMERA_FRAME chunks          (CMD CAMERA_STREAM / SNAPSHOT)
  SD      <-> storage: .zact actions, audio, /img/<id>.jpg
```

Everything enters through `zlink_server.c` (UDP task, TCP task), which calls `app.c: on_frame()`. The dispatcher hands each
message to one component:

| Message | Handled by |
|---|---|
| HELLO / PING (reply HELLO_ACK with `fw_ver` bit 15, PONG) | `app.c` |
| JOINT_TARGETS, TRAJ_CHUNK, STREAM_START / STREAM_END | `app.c` -> `motion` |
| AUDIO_CHUNK (PCM16 16/24 kHz; Opus is ignored) | `app.c` -> `audio` |
| CMD 0-7 HOLD, ESTOP, TORQUE_ON, GO_HOME, PLAY_FILE, SET_RATE, CALIB_SET (+ optional `ticks_per_rev`), CALIB_SAVE | `app.c` -> `motion` / `audio` / `storage` |
| CMD 8 CALIB_GET -> CALIB_REPORT (sent before the ACK) | `app.c` -> `motion_calib_get` |
| CMD 9 MIC_STREAM (PCM16 16 kHz only) -> MIC_CHUNK over UDP | `app_media.c` -> `audio` |
| CMD 10 CAMERA_STREAM, 13 SNAPSHOT -> CAMERA_FRAME chunks (<= 1360 B) over UDP | `app_media.c` -> `camera` |
| CMD 11 SET_VOLUME / 12 SET_BRIGHTNESS | `app_media.c` -> `audio` / `display` (backlight PWM) |
| FACE_SET, FACE_PARAMS, FACE_TRACK | `app_media.c` -> `display` (`face_engine` + `face_sdf`) |
| DISPLAY_IMAGE (TCP) -> `img_asm` -> `zjpeg` hardware decode -> show and/or SD `/img/<id>.jpg`; then EVENT IMAGE_DONE + ACK | `app_media.c` -> `display` |
| DISPLAY_TEXT, DISPLAY_MODE | `app_media.c` -> `display` |
| STATE (50 Hz, 96 B: tail = `stream_buffered_ms`, `stream_pos_ms` from `motion`; `display_mode`, `emotion` from `display`) | `app.c` |
| EVENT (state, stream/file done, watchdog, fault, estop, IMAGE_DONE) | `app.c` / `app_media.c` |

Face behaviour (`display/face_engine.c`, same as `FaceAnimator` in the studio): FACE_SET blends from the current
parameters to neutral->emotion at `intensity/255` over `blend_ms` (hue the short way round, symbol and wink switch at
the midpoint; the `gaze` bytes are added to the emotion's own gaze, in px). FACE_PARAMS edits the target (sticky until
the next FACE_SET). FACE_TRACK keys play on the motion stream clock while the stream with that `stream_id` runs; the
face blends back to the last explicit face when it ends. Idle: blink every 2.5-5.5 s for 140 ms and a small gaze drift
(off with the hold flag); the talking flag drives `mouth_open`. The renderer redraws only the union of the old and
new bounding box.

`main/app_main.c` only wires things together. A driver whose pins are `-1` or whose hardware is missing is skipped,
and the robot still boots.

## Safety model

1. The AI stack's safety stage (joint limits, collisions, balance) checks everything before it is sent.
2. Firmware is the last line. Every target passes the limiter (position clamp to `robot.json` limits, velocity and
   acceleration limits with a braking curve, no overshoot). Stale targets older than 200 ms are dropped. With no host
   frame for 500 ms during a stream, the robot goes to HOLD. Servo read failures are reported as FAULT.
3. Torque is off at boot (state IDLE) and turns on only with `CMD TORQUE_ON`. That requires a **saved calibration**
   (Kconfig `ZANG_MOTION_ALLOW_UNCALIBRATED` overrides this for bench bring-up). `CMD ESTOP` turns torque off and latches.

## Calibration (first bring-up)

1. Flash, connect, and send `HELLO`. Servos are limp and STATE shows `q_meas` computed with the default calibration
   (zero = 2048, sign +1), so the host can recover the raw ticks.
2. Pose the robot in the model's home pose (`robot.json` `home`). For each joint, send `CMD CALIB_SET index, zero_ticks, sign`.
   Check the sign by moving one joint by hand and watching `q_meas`.
3. `CMD CALIB_SAVE` → NVS. From then on `TORQUE_ON` is allowed.

## What is stubbed or unverified

- **Servo**: no DS-R003G datasheet. The resolution (4096 ticks / 270°), baud rate and SYNC WRITE are unverified;
  SYNC WRITE is off by default. With per-servo writes at 115200 baud, the motion loop runs at 50 Hz.
- **LVGL**: not integrated. The face is drawn by our own canvas, which is lighter. Add `esp_lvgl_port` if menus are needed.
- **Audio**: WAV/PCM only. No MP3 decoder yet (`esp_audio_codec` would add one). Opus `AUDIO_CHUNK` is ignored with a
  warning. `MIC_STREAM` supports 16 kHz PCM16 mono only (codec 1/2 and the stereo option answer NOT_SUPPORTED);
  `ZANG_STREAM_MIC` starts the stream at boot for bench work.
- **Camera / images**: the JPEG hardware decoder (`zjpeg.c`), the camera size switch (rebuilds the DVP controller) and
  the SD image store are written against the IDF headers and compile, but nothing has run on hardware. Baseline JPEG
  only (no progressive). Scaling is nearest neighbour. DISPLAY_IMAGE with raw RGB565 must be 240x240 and cannot be stored.
- **Faces**: the renderer matches the Python goldens (host tests). Frame time on the P4 is an estimate (`make test` prints the host
  time from `test_host/face_bench`), not a measurement.
- **IMU**: absent on v0.0.1. STATE sends `0x7FFF` for rpy/gyro/acc.
- **C2 flashing through the P4** (esp-serial-flasher): documented as a later option. Only `net_c2_reset(true)` exists.
- Nothing has run on hardware yet. Everything above compiles, and the pure modules pass the host tests.
- ZLink FACE_TRACK: up to 100 keys per message (`ZLINK_FACE_MAX_KEYS`, as `ai_stack` sends); the player keeps 256 keys.
